# 迭代任务：为 PolicyPulse 增加「信号可投资性闸门」与「深读结论反向分区」

> 这是给另一个 coding agent 的执行提示词。改完要能自证：今天（10-21）的 APEC 会议稿不再进"受益"表，20 号的真实政策信号不被误杀。

## 一、项目背景

PolicyPulse 是一个个人自用、单机、单进程的 A 股**政策受益股监测工具**：每天抓取中央与部委的会议/政策通稿，抽取政策信号，映射到行业板块与个股，产出一份"每条结论都能点回原文"的潜在受益个股排序。

- 仓库根：`/Users/juzhongsun/Codes/pythons/PolicyPulse`（editable 安装，Python ≥3.10，当前 pyenv 环境 `policypulse` / 3.12.4）
- 主入口：`policypulse run`（抓取→抽信号→事件聚类→板块映射→公司级相关性闸门→打分→深度研读→落库→出日报 md/html/json）
- 本项目核心红线：**每条结论可回溯到原文/公司公开源；宁缺勿错**。

## 二、本次只改什么 / 不碰什么

只做**两处行为变更 + 一个建议项**。**不要**改动：窗口口径（today-window）、`sources.yaml`、公司级相关性闸门（`policypulse/relevance.py`）、抓取合规逻辑、打分权重结构（除非本需求明确要求）。

## 三、现状问题（先读证据）

读 `reports/2026-10-21.md`（今天实际跑出的日报）。核心问题：

- 窗口内只抓到 1 篇"2026年亚太经合组织财长会在香港举行"（财政部 10-21）。
- LLM 把其中"扩大内需、高水平对外开放"这类**泛经济样板表述**抽成主题「新零售」，进而展开 10 只"新零售"概念股（中国中免 / 小商品城 / 永辉超市 / 九安医疗 / 供销大集等）。
- 该信号自己的 3 条深度研读**全部**判"中性 / 无实质传导 / 关联度低"，但日报仍把它呈现为「政策事件与候选个股 · 受益」Top-10 表——**自相矛盾**。
- 根因：管线已有公司级相关性闸门，但**缺少信号级"可投资性"判断**；抽主题这步把样板经济话硬标成具体板块，下游忠实放大，公司级闸门救不了标错的上游主题。

## 四、改动 1：信号级可投资性闸门

**目的**：泛经济样板表述不得映射板块、不得进"受益"表；要求信号含**具名产业 / 具体项目 / 量化措施**才算可投资。

- 在信号抽取后、`match_sectors` / `build_candidates` 之前插入判定（建议新增模块 `policypulse/investability.py`，或在 `extract.py` / `pipeline.py` 内实现）。
- 给 `Signal` 增加字段 `investable: bool`（**保守默认：不确定即 False**）。
- 判定规则（**确定性，不依赖 LLM**）：
  1. 定义 `GENERIC_POLICY_MARKERS` 泛样板词表（示例）：`扩大内需`、`高质量发展`、`高水平对外开放`、`经济持续向好`、`增长新动能`、`新发展格局`、`双循环`、`中国式现代化`、`深化改革开放`、`稳中求进`。
  2. 定义"具名产业/具体性"命中：信号文本（summary + quote）是否含具体产业/领域词。可复用 `load_theme_business()` 的关键词集，并补充常用具名产业词（新能源汽车、人工智能、碳市场、工业母机、职业教育、养老服务、数字经济、低空经济、数据要素……）。
  3. 命中 ≥1 泛样板词 **且** 不含具体产业词 → `investable=False`；否则 `investable=True`。
  4. `investable=False` 的信号：**仍入库**（可审计），但**跳过板块匹配与个股展开**，划入日报「非投资信号」区（见改动 3）。
- 配置：`Settings` 加开关 `investable_gate: bool = True`（默认开，可关）。样板词表可外置为 `data/` 下 CSV 或内置常量，二选一。

## 五、改动 2：深读结论反向分区

**目的**：让深度研读的传导判断**反向决定报告分区**——判"直接/间接实质传导"才是"受益个股"；判"中性/无实质"降级到「仅概念关联」，不授予"受益"头衔。

- 读 `policypulse/deepdive.py` 的 `DeepDive.transmission` 字段。定义**确定性映射**：
  - 含"直接"、"间接"（且非"间接情绪面 / 间接、无实质"这类否定）→ **实质传导**
  - 含"中性"、"无实质传导"、"关联度低"、"影响有限"、"缺乏具体措施" → **无实质传导**
- 每个 policy event：取其 Top 个股的深读结论，若全部/多数判"无实质传导" → 该事件降级到「仅概念关联」区；否则进「受益个股」区。
- 未配 LLM（无深读）时：保持现有行为，但报告框架上把该事件标为「概念关联（未做实质传导判定）」，而非"受益"。

## 六、改动 3（建议做）：空信号日 / 报告分区表达

- 报告新增/调整分区，优先级：`受益个股`（investable 且实质传导）> `仅概念关联`（investable 但无实质传导，或无深读）> `非投资信号`（investable=False 的泛话，一行一条 + 原因）。
- 若某日没有任何"受益个股"，报告明确写「今日无实质投资信号」，并展示 仅概念关联 / 非投资信号，**不生成空的"受益"表**。
- md / html / json 三端一致；json 的 conclusion / event 增加 `investable` 与 `section` 字段。

## 七、兼容与约束

- 不破坏既有 DB 与命令：`policypulse run / show / verify / sources / selftest` 都要正常。新增字段若入库优先用"新列带默认值"的兼容方式；也可只在结论 dict 与 json 中携带而不改表结构——自行权衡，**保持向后兼容**。
- 溯源红线不变：所有产出可点回原文 / 公司公开源；深读的红线校验（`deepdive.py` 的 `validate`）不得因分区而放宽。
- 宁缺勿错：判定不确定时按"非投资 / 仅概念关联"处理，不按"受益"。
- 中文输出。
